# 智能体驱动建模架构

项目的可复用成果是完整研究闭环：问题与物理约束 → 研究工作流 → MCP 工具 → 保存源码及受控执行 → 独立验收 → 诊断修订或成稿。Litz 提供真实数值案例与明确的未解决边界。

automation/ 保存任务、技能、客户端配置与真实调用；adapters/ 负责软件连接和执行；models/ 保存科学实现，shared/ 保存共用数值、路径及显示代码。CLI 与原生 Notebook 共用 Python 任务接口，Wolfram MCP 案例也调用同一受控运行器。Ansys MCP 在 CPython/PyAEDT 中调用已保存的原生适配代码。

正式运行前保存参数、源码字节与哈希；运行中保存环境、所属进程、资源采样及日志；结束后保存结构化结果、原生数值对象、容差与验收。工具记录区分初始化、工具发现、请求和响应；修订保留原失败、实际差异及新运行身份。公开副本只规范机器路径，核对全部 JSON 数值位置不变。

jobs submit 返回运行号，status 查询所属任务，cancel 请求取消。教程接续核对原请求与源码快照后，以新身份重新执行保存输入，并记录当前源码的变化。完整计算使用各路线实际支持的检查点；未支持的恢复按重新运行说明。

所属进程继承八个逻辑处理器约束，运行器监测 24 GiB 任务内存、8 GiB 系统空闲内存及超时。Ansys 另记录明确的 Student PID、gRPC 会话与四核求解限制。大型计算串行执行；清理进程须核对创建身份。Notebook 保存完成回执与后续辅助进程清理分别记录，保留真实退出码。

连接、工具调用、求解与物理验收各有独立状态。API 可能返回 isError=false 的错误文本，仍须判定失败。预算耗尽、中断、不收敛和物理失败保留实际状态。共同端电压与总电流联立求复电流；外场损耗、几何观察和输运电阻分别解释。A–φ 显示及采样使用原保存场，原规范失败继续保留。

从[方法与证据对应表](method-evidence-map.zh-CN.md)、[真实案例](../automation/examples/verification.json)和[来源体系](../references/README.zh-CN.md)继续研究。Codex 经标准 MCP 客户端桥接完成端到端验收；其他客户端按实际测试状态记录。

Ansys 的 maxwell-seven 案例已接入统一任务接口，实际验收了提交、状态、取消、会话关闭及新身份接续。详见 provenance/rc2/native_task_lifecycle.json。
